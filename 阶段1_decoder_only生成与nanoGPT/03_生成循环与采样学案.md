# 学案 03｜生成循环与采样

## 1. 生成循环的最小状态机

假设当前上下文 token 是 `idx`，形状 `(B,T_current)`。每轮生成做：

```text
1. 截断上下文到模型允许的 block_size
2. model(idx_cond) 得到 logits (B,T_cond,V)
3. 取最后一个位置 logits[:, -1, :]（B,V）
4. 按解码策略得到下一个 token ID
5. 追加到 idx
6. 遇到 stop token 或达到 max_new_tokens 时停止
```

模型输出整个序列每个位置的分布，但本轮只需要最后一个位置，因为它代表“接下来要生成什么”。

## 2. Greedy、随机采样与温度

**Greedy decoding** 直接取最大 logit 的 ID：

```text
next_id = argmax(logits)
```

它可复现，但容易重复、缺少多样性。

**随机采样** 先把 logits 变成概率，再按分类分布抽样：

```text
p_i = exp(logit_i) / Σ_j exp(logit_j)
```

**Temperature** 在 softmax 前除以 `τ`：

- `τ<1`：分布更尖，偏向高概率 token；
- `τ=1`：原始分布；
- `τ>1`：分布更平，增加探索。

温度不是质量旋钮，也不是训练；过高会产生不连贯 token，过低可能重复。

## 3. Top-k 与 top-p

**Top-k** 只保留分数最高的 k 个 token，其余概率设为 0。k 太小会截断合理续写，k 太大时接近原始采样。

**Top-p / nucleus sampling** 按概率从高到低排序，只保留累计概率达到 `p` 的最小集合。每一步保留的 token 数量会变化：分布尖时少，分布平时多。

实现时必须：

1. 在过滤前保存排序索引；
2. 过滤后重新归一化概率；
3. 至少保留一个 token，避免全为 0；
4. 明确 top-k 与 top-p 的先后顺序，并在实验记录中写出。

## 4. 数值与控制边界

- logits 可能很大，直接 `exp` 容易溢出；用 `softmax` 或 `log_softmax` 的稳定实现。
- `temperature<=0` 应显式处理为 greedy 或报错，不能静默除零。
- `max_new_tokens` 是新增 token 数，不是最终序列总长度。
- `block_size` 限制模型能看到的上下文；超出时通常保留末尾窗口。
- `stop_id` 要属于 tokenizer 词表；没有停止 token 时必须依赖最大步数。
- 推理时使用 `model.eval()` 和 `torch.no_grad()`；它们分别控制模块行为和梯度记录。
- 固定随机种子只保证在相同软件/设备条件下更容易复现，不保证所有硬件完全一致。

## 5. 为什么生成是 token 级循环

生成字符串不能一次性由模型输出，因为第 `t+1` 个条件包含第 `t` 个新 token。一个循环的正确性比“生成看起来像英语”更重要。调试时先用一个假模型或固定 logits，检查：

```text
输入长度每轮 +1
取的是最后位置
追加维度正确
停止条件确实生效
```
